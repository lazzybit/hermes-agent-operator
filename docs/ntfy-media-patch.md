# ntfy native media patch

`gateway/patches/ntfy-media.patch` extends the official Hermes v0.23.0 ntfy adapter with native local image/document uploads and a platform hint teaching `MEDIA:`. It follows https://docs.ntfy.sh/publish/#attachments: PUT binary bytes, always X-Filename (including small UTF-8 files), optional X-Message caption and RFC 2047 UTF-8 headers. ntfy produces attachment metadata and client previews/download controls. X-Tags retains hermes-agent echo protection. Remote image URLs use native X-Attach. Successful HTTP responses without attachment metadata are treated as failures.

`gateway/patches/ssh-media-reconnect.patch` complements the existing session-scope patch: when no active SSH environment remains at delivery time, reinitialize only the explicitly scoped session under the caller's profile policy. Do not recreate other remote backends or invent a default session. Strict delivery policy still refuses before environment initialization; path and symlink checks remain unchanged. Live end-to-end acceptance must verify profile scope and remote fetch, not infer success from a unit test.

Both patches apply at image build with git apply --check. Remove each override only when the pinned upstream provides equivalent behavior and its candidate-image regression passes. `gateway/test-ntfy-media.py` tests the native HTTP contract; `gateway/test-ssh-media.py` tests scoped remote retrieval. Candidate CI executes both inside the built image before publishing. Standalone cron media remains outside this patch's scope; live Gateway MEDIA delivery is the supported path.
